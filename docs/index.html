Open the vote

Publishing encrypts the candidate list in this browser and sends it to members' devices. The server stores only ciphertext and cannot read it.

Candidates appear as "Candidate 1", "Candidate 2" in a shuffled order, and key publications are withheld since a title identifies the author. Institution, career stage and metrics stay visible. What this tool stores, and where

Stays on the chair's device

Candidate names, institutions, career stages, gender, metrics and key publications are typed into the chair's browser and held there. Before the list is sent to committee members it is encrypted in that browser with AES-256-GCM. The key travels to members inside their seat link, in the part after the #, which browsers never transmit to a server. The server therefore holds ciphertext it has no key for.

Held on the server during a session

  • The encrypted candidate list, unreadable without the key.
  • A one-way hash of each seat token, and whether that seat has voted.
  • A count per candidate identifier. The identifiers are random strings, not names.

These sit in two separate tables with no column joining them, which is why no one — including the chair, and including whoever operates the server — can determine how any member voted. That is a property of the schema, not a promise.

Where it physically sits

On Cloudflare Workers, in a storage object pinned to the European Union, so processing and storage stay in the region. The object's random identifier is logged outside that region for billing and diagnostics; it contains no personal data.

How long

Until the chair presses "Delete all session data", which erases everything for that session immediately. Automatic deletion once voting ends is not yet implemented and is the next change planned. The chair's own working copy lives in the browser tab and disappears when that tab is closed.

What leaves, and only if asked

Nothing is transmitted to AKC's open dataset unless a chair explicitly chooses to contribute, and the exact record is shown before it is sent. It contains coarse buckets only — no names, no institutions, no exact counts, no dates finer than a quarter, and no reference to the session it came from. It is anonymous rather than pseudonymous, which is why it can be published openly. Ticking the opt-out box when opening a session removes the option altogether.

No tracking of any kind

No cookies, no analytics, no tracking, no advertising, no third-party scripts, and no accounts. Candidate data is never used to train anything.

Who is responsible

The committee running the selection is the controller of its candidates' data and is responsible for informing them, for its own legal basis, and for retention. AKC supplies the software and operates the open dataset.

Limitations

  • It does not detect bias it has not been told to look for, including racial, disability and socioeconomic bias.
  • It cannot verify the data entered. A wrong h-index produces a confident wrong flag.
  • Gender is recorded as entered by the chair, not as self-identified by the candidate.
  • Double-blind mode hides names and gender from members, but a career stage, an institution and an h-index may still identify someone in a small field. It reduces bias; it does not guarantee anonymity. The chair is never blind.
  • It has no memory across sessions, so it cannot yet show your committee's patterns over time.
  • The chair knows which seat link went to which person, but never learns which ballot came from which seat.
